# 标看看｜监理标讯助手｜真实数据试点 MVP PRD

> 状态：页面拆分已实现并通过本地验收，其余条目按验收清单推进｜更新时间：2026-08-20

> 一句话：每天自动巡检 5 个已接入的招标网站，把真实的监理项目、截止时间和原公告入口整理到同一个网站，并生成一份真实的每日汇总数据。

> **本版覆盖旧规定：**当前不扩展到 10–20 个网站，不接真实企业微信，不建设项目数据库；先验证“发现项目—查看详情—打开原公告—生成每日汇总”能否稳定工作。

## 1. 这是什么？

本版做一个**网站**，不是本地软件；电脑端方便查看项目表格，手机端可直接打开网站查看项目列表和详情。

本版只做一件事：**找项目、看关键信息、关注截止时间。**

投标经理每天要打开很多网站：公共资源交易中心、政府采购网站、招标代理机构官网……然后逐条点开公告，找下面这些信息：

- 是不是监理项目；
- 项目叫什么、是哪一个标段；
- 规模有多大；
- 谁是招标人；
- 哪一家是招标代理机构；
- 最晚什么时候投标。

这件事看似简单，但很耗时间，也很容易漏掉公告、变更公告或临近截止的项目。

我们要提供的不是更多公告，而是一个每天自动工作的“雷达”：把分散信息汇总为一张清晰的项目表，并在临近截止时提醒用户。

---

## 2. 项目边界

**本版只服务一家试点公司，只接入 5 个已确认来源。** 系统每天扫描一次，提供项目列表、项目详情、原公告跳转、信息源管理和运行异常，并生成每日汇总数据。

产品介绍页和业务工作台必须是两个独立页面：介绍页负责让第一次访问的人理解产品，项目雷达负责让投标人员完成日常工作。两者不得在同一个 URL 中上下拼接成长页面。

本版不接真实企业微信群机器人，也不做独立提醒中心、消息预览、模拟发送、发送记录、提醒类型配置、接收群配置、个人订阅、多个群、已读状态或项目认领。每日汇总只作为经过验证的数据产物保存，后续接入企业微信时直接复用。

本版使用可发布的 JSON 快照保存项目、来源、扫描和汇总结果，不建设数据库。信息源存储和项目存储必须通过统一接口访问，后续换成数据库时不改页面数据结构和抓取适配器。

管理员通过页面新增的网址先成为“候选来源”，只保存在当前设备，尚不参与自动扫描。只有完成抓取适配和验证的来源才显示为“已接入”。

本版也不做：判断项目能不能投、适合度或机会评分、项目分派、团队协作、审批、商务情报、自动投标和投标文件制作。这些能力不在页面上放灰色入口，避免用户误以为已经可用。

系统负责发现和整理；投标经理仍以原公告和招标文件为准。后续是否增加数据库、企业微信和更多来源，等本版真实数据稳定后再决定。

## 5. 本版长什么样？

### 5.1 页面分工与路由

| 路由 | 页面职责 | 必须包含 | 不应包含 |
|---|---|---|---|
| `/` | Landing Page，教育第一次访问的用户 | 产品定位、工作方式、产品边界、进入项目雷达按钮、隐私与服务说明 | 项目表格、搜索筛选、项目详情、系统管理 |
| `/radar` | 投标人员日常使用的项目工作台 | 今日新增、3 天内截止、全部项目、搜索筛选、真实项目列表 | Landing Page 的营销内容、长篇产品说明、公开页页脚 |
| `/radar/project?id={项目ID}` | 单个项目详情 | 完整字段、原公告摘要、发现时间、扫描时间、更新时间、原公告按钮 | 其他项目的公告链接、静态演示字段 |
| `/radar/admin` | 管理员工作台 | 信息源管理、候选来源、运行异常、最近扫描状态 | Landing Page 内容、项目营销展示 |

页面跳转规则：

- Landing Page 顶部和首屏的“进入项目雷达”都跳转到 `/radar`；
- 项目名称和“查看详情”跳转到带项目 ID 的详情 URL；
- 项目雷达与系统管理通过顶部工作台导航互相切换；
- 点击工作台品牌标识返回 `/`；
- 上述 URL 必须支持直接打开和浏览器刷新，不能依赖用户先访问首页；
- 手机端保留相同路由和数据，只调整布局，不删除原公告与详情入口。

### 5.2 Landing Page：告诉用户产品有什么用

Landing Page 只做简单教育，不承担项目处理任务。首屏回答三个问题：这是监理标讯助手、每天整理 5 个已接入来源、所有项目都能回到原公告核验。

页面依次展示：

1. 产品定位与“进入项目雷达”主按钮；
2. 真实数据闭环，包括来源数量、每日汇总、项目与公告一一对应、链接异常降级和待核验原则；
3. 工作方式，包括每天巡检、整理关键信息、生成每日汇总；
4. 产品边界，包括不替代原公告、不猜测字段、不做评分和自动投标；
5. 隐私说明、服务条款和备案信息。

Landing Page 不展示真实项目表、搜索框、项目筛选、管理后台或详情页。用户点击主按钮后进入独立工作台，而不是滚动到同一页面下方。

### 5.3 项目雷达：投标经理每天看的项目表

项目雷达默认打开“今日新增”。用户也可以切换到“3 天内截止”和“全部项目”。

| 截止时间 | 项目名称 | 标段 | 总投资 | 招标人 | 招标代理机构 | 来源 | 原公告 |
|---|---|---|---:|---|---|---|---|
| 8月25日 09:30 | 通许县宏达大道排水管网改造工程 | 第二标段 | 6,961.37 万元 | 通许县城市管理局 | 河南省开兴工程管理咨询有限公司 | 开封市公共资源交易中心 | 查看 |

页面规则很简单：

- **截止时间永远放在第一列**；
- 剩余 3 天以内显示黄色；
- 剩余 1 天以内显示红色；
- 已过截止时间显示“已截止”；
- 系统没能可靠识别时间时，显示“待核验”；
- 点击项目名称看详情；点击“查看”打开原公告。

项目雷达中的项目必须来自最近一次真实扫描。数据文件无法读取时显示“项目数据暂时无法读取”，从未扫描时显示“等待首次扫描”，扫描成功但没有项目时显示“本次扫描未发现监理项目”。**任何失败状态都不能退回静态 Demo 项目，也不能继续显示“扫描正常”。**

### 5.4 项目详情页：不用再在公告里找半天

详情页把系统识别出的内容整理好：

```text
项目名称：通许县宏达大道（人民路-第一污水处理厂）排水管网改造工程
标段：第二标段
投标截止：2026-08-25 09:30
总投资：6,961.37 万元
招标人：通许县城市管理局（通许县城市综合执法局）
招标代理机构：河南省开兴工程管理咨询有限公司
信息来源：开封市公共资源交易中心

[打开原公告]
```

详情页还要有：

- 原始公告标题；
- 公告发布时间；
- 项目地区（能够识别时展示）；
- 公告正文或相关原文片段；
- 系统发现时间和最后更新时间；
- 相关的补充、变更、暂停或终止公告；
- “待核验”提示。

### 5.5 原公告打不开时怎么处理

每次扫描同时验证项目的原公告、该来源的公告列表页和网站主页，并记录最后验证时间。

每个正式项目至少保存以下链接核验字段：

```json
{
  "originalUrl": "项目自己的原公告地址",
  "listUrl": "该来源的公告列表地址",
  "homeUrl": "该来源的网站主页",
  "linkStatus": "available | original_unavailable | source_unavailable",
  "lastVerifiedAt": "2026-08-20T07:42:00+08:00",
  "linkFailureReason": "原公告返回 404"
}
```

| 最近一次验证结果 | 用户看到什么 | 点击后发生什么 |
|---|---|---|
| 原公告有效 | 打开原公告 | 打开该项目自己的公告详情页 |
| 原公告无效，列表页有效 | 原公告不可用 · 打开公告列表 | 先提示“原公告暂时无法访问”，用户确认后打开列表页 |
| 原公告和列表页无效，主页有效 | 原公告不可用 · 打开来源主页 | 先提示“原公告暂时无法访问”，用户确认后打开主页 |
| 三个入口都无效 | 链接不可用，请人工核验 | 不跳转，展示最后核验时间和失败原因 |

链接状态来自最近一次云端扫描，不承诺每次点击前实时检测。**系统绝不能把其他项目的公告链接当作当前项目的备用链接。**

页面使用旧快照时，在项目列表顶部显示：

```text
当前显示上次成功扫描数据
扫描时间：2026-08-20 07:42
部分来源本次访问失败，请以原公告为准。
```

## 6. 系统每天做什么？

### 第一步：访问已配置的网站

本版只扫描以下 5 个已接入来源，不自动导入其他候选网站：

| 来源 | 网站主页 | 工程建设公告入口 |
|---|---|---|
| 河南省公共资源交易中心 | `https://hnsggzyjy.henan.gov.cn/` | `https://hnsggzyjy.henan.gov.cn/jyxx/002001/transaction_notice.html` |
| 开封市公共资源交易中心 | `https://www.kfsggzyjyw.cn/` | `https://www.kfsggzyjyw.cn/jzbgg/index.jhtml` |
| 郑州市公共资源交易中心 | `https://zzggzy.zhengzhou.gov.cn/` | `https://zzggzy.zhengzhou.gov.cn/jsgc/004001/subpage.html` |
| 新乡市公共资源交易中心 | `https://ggzy.xinxiang.gov.cn/` | `https://ggzy.xinxiang.gov.cn/jyxx/trade.html` |
| 洛阳市公共资源交易中心 | `https://lyggzyjy.ly.gov.cn/` | `https://lyggzyjy.ly.gov.cn/jyxx/transaction.html` |

以上 5 个工程公告入口已于 2026-08-20 完成 HTTP 可访问性核验，均返回成功状态。该结果不代表永久可用；定时扫描仍须按 5.5 记录每次核验状态，失败时明确提示，不能私自替换来源或项目链接。

河南省政府采购网和河南兴达工程咨询官网不属于本版默认来源。系统每天 07:30（北京时间）扫描一次；本版不安排 14:30 的第二次定时扫描。

### 第二步：找到监理相关公告

系统从公告列表中查找包含这些词的内容：

```text
监理、工程监理、施工监理、建设工程监理、
项目管理及监理、全过程工程咨询
```

本版故意采用较宽松的规则：宁可让少量不完全相关的公告进入列表，也不要漏掉真正的监理项目。

### 第三步：进入详情页找关键信息

系统需要从公告正文、表格和可读取附件中，找出以下字段。

| 字段 | 为什么重要 | 本版要求 |
|---|---|---|
| 项目名称 | 判断项目是什么 | 必须 |
| 标段 | 判断具体投哪个包 | 必须 |
| 投标截止时间 | 决定是否来得及处理 | 必须 |
| 招标人 | 识别客户和项目归属 | 必须 |
| 招标代理机构 | 方便联系和追踪 | 必须 |
| 总投资 | 快速判断项目规模 | 尽量提取 |
| 公告发布时间 | 判断公告新旧 | 尽量提取 |
| 项目地区 | 后续按地区查看 | 尽量提取 |
| 原公告链接 | 人工核验和继续操作 | 必须 |

系统识别不出来的字段，只能显示“待核验”，不能猜。

### 第四步：验证项目和链接

项目写入快照前必须满足：

1. 项目来源属于当前 5 个已接入来源；
2. 项目有自己的原公告 URL，不能使用样例项目或其他项目 URL；
3. 公告标题或正文能够与项目名称对应；
4. 原公告无法访问时，记录失败原因并按 5.5 的规则降级；
5. 无法证明项目来自真实公告时，不进入正式项目列表，写入运行异常。

### 第五步：合并重复信息，保留变化

同一项目可能出现在多个页面，也可能发出补充或变更公告。

系统优先按以下信息识别重复：

1. 原公告链接；
2. 项目编号和标段；
3. 项目名称、招标人、截止时间的相似程度。

变更、补充、暂停和终止公告不能覆盖或删除原记录；它们应显示在同一个项目详情页里，并告诉用户“该项目有更新”。

## 7. 每日汇总怎么生成？

扫描完成后，系统从当天真实项目快照生成一份汇总数据。网站不提供提醒中心、消息预览、模拟发送或发送记录页面。下列内容只说明数据结构，不得作为线上无数据时的备用内容。

```json
{
  "date": "2026-08-20",
  "newProjectCount": 5,
  "expiringWithin3DaysCount": 2,
  "earliestProjects": [
    {
      "projectId": 633942592,
      "name": "通许县宏达大道排水管网改造工程",
      "section": "第二标段",
      "deadline": "2026-08-25 09:30"
    }
  ],
  "abnormalSourceCount": 0
}
```

| 规则 | 本版做法 |
|---|---|
| 生成时间 | 每天扫描完成后生成 |
| 生成次数 | 同一天只保留一份；重复扫描更新同一记录 |
| 今日新增 | 按系统首次发现时间计算，不按公告发布时间代替 |
| 临期项目 | 截止时间在未来 3 天内，已截止项目不计入 |
| 最早截止 | 最多 3 个，按截止时间从早到晚排列 |
| 没有新项目 | `newProjectCount` 为 0，仍保留临期数量 |
| 部分来源失败 | `abnormalSourceCount` 记录异常来源数量 |

汇总中的项目必须存在于当前项目快照，数量必须由同一份项目数据计算。当前不调用企业微信接口；后续发送器直接读取这份汇总，不另写一套统计逻辑。

## 8. 管理员需要的后台

管理员不需要复杂后台，本版只要两个页面。

### 信息源管理

| 内容 | 作用 |
|---|---|
| 网站名称 | 知道扫描的是哪个来源 |
| 网站主页 / 公告列表页 | 原公告失败时提供明确的降级入口 |
| 地区 | 方便管理来源覆盖范围 |
| 来源类型 | 交易中心、采购网、代理机构官网等 |
| 接入状态 | 已接入、候选、待适配、已停用或异常 |
| 是否启用 | 临时停止或恢复扫描 |
| 最后扫描时间 | 确认是否按时工作 |
| 扫描结果 | 成功、部分失败或失败 |

页面顶部显示：

```text
已接入 5　候选 2　已停用 0　异常 0
```

管理员新增 URL 后，系统只保存为“候选来源”，并显示：

```text
候选来源 · 仅保存在当前设备
尚未参与自动扫描
```

候选来源不能显示“扫描正常”。完成抓取适配和真实公告验证后，开发将其加入统一来源配置，状态才变成“已接入”。本版新增、编辑和删除候选来源只影响当前浏览器。

扫描进度和最近一次扫描结果直接显示在信息源管理页，不另做“扫描状态”页面。

### 运行异常

网站改版、访问失败、项目与公告无法对应、原公告链接失效或必填字段无法识别时，后台显示异常记录。管理员能看到发生时间、异常类型、对应来源、项目和最近一次结果；本版不提供前端重试按钮。

## 9. 产品形态和系统结构

### 品牌和域名

- 品牌名：**标看看**；
- 产品全称：**标看看｜监理标讯助手**；
- 主域名：`biaokankan.com`；
- 保护性备用域名：`biaokankan.cn`；
- 本版对外页面和正式链接统一使用 `https://biaokankan.com`；后续接入企业微信时，消息链接也必须使用同一主域名；
- `biaokankan.cn` 在纳入备案并配置 HTTPS 后，跳转到 `https://biaokankan.com` 的对应页面，不建设第二套独立网站。

**`biaokankan.com` 是唯一首发主域名，`biaokankan.cn` 作为保护性备用域名。** 首次 ICP 备案只使用 `biaokankan.com`；`biaokankan.cn` 暂不解析，待后续纳入备案后再启用跳转。

### 为什么本版是网站？

- 招标扫描应在云端统一运行，不依赖某台电脑开机；
- 投标经理在电脑上看表格和打开原公告更高效；
- 手机可以直接打开项目列表和详情；
- 网站更新后所有用户立即使用最新版本；
- 不需要安装、升级本地 PC 软件，也暂不需要投入原生 iOS App 开发。

### 系统如何组成？

```text
公开招标网站
      ↓
云端扫描服务（每日一次）
      ↓
解析服务（提取项目、标段、截止时间等）
      ↓
JSON 快照存储（去重、更新、链接状态、汇总计算）
      ├── Landing Page：产品介绍、工作方式和产品边界
      ├── 项目工作台：项目列表、详情、信息源后台
      └── 每日汇总数据：后续企业微信发送器直接读取
```

项目、来源和扫描结果分别通过 `ProjectStore`、`SourceStore` 和 `RunStore` 接口访问。当前实现写入 JSON；后续数据库实现必须遵守同一数据结构，页面和抓取适配器不直接依赖 JSON 文件路径。

## 10. 规则与底线

1. 系统只处理公开、允许访问的公告信息；
2. 不绕过登录、验证码、付费墙或其他访问控制；
3. 对每个网站控制访问频率，避免给来源网站造成压力；
4. 原公告和招标文件是唯一最终依据；
5. 系统无法确定的信息，必须提示用户核验；
6. 一个项目只能使用自己的原公告链接，不能使用样例或其他项目链接；
7. 原公告失效时必须明确告诉用户“无法访问”，再提供列表页或主页；
8. 数据读取失败时不能显示静态 Demo 项目，也不能显示“扫描正常”；
9. 每日汇总只能从当次真实项目快照生成；
10. 本版不保存、展示或调用企业微信群机器人地址。

## 12. 本版之后做什么？

先观察 3 个数据：

1. 5 个来源每天能稳定扫描多少次、失败多少次；
2. 每天发现多少条真实监理公告，多少字段需要人工核验；
3. 投标经理认为“有用、值得继续打开原公告”的项目比例。

真实数据稳定后，再单独立项：

1. 接入云端数据库，让项目、来源和运行记录集中保存；
2. 将“添加信息源”改为所有管理员共享，并逐站完成适配后加入扫描；
3. 配置一个固定企业微信群机器人，每天 08:30 发送当前汇总数据；
4. 根据实际使用需求逐步增加来源，不预设必须一次扩展到 18 个；
5. 再评估地区订阅、工程类型筛选和资格条件提取。
