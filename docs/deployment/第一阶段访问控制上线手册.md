# 标看看｜第一阶段访问控制上线手册

> 对应需求：[PRD_002B｜ECS 访问控制与企业账号](../prd/PRD_002B_ECS访问控制与企业账号.md)
>
> 当前边界：可以在 ECS 回环地址或 SSH 隧道中配置和验收；ICP 通过、HTTPS 证书生效前，不向企业用户开放公网入口。

## 1. 上线结果

| 访问方式 | 预期结果 |
|---|---|
| 正博星元已登记的公网出口 IP | 直接进入，不显示密码框 |
| 其他网络、手机流量 | 浏览器要求输入企业专属凭证 |
| 错误或已撤销凭证 | 返回 401；15 分钟内失败 5 次后封禁 15 分钟 |
| HTTP | 只跳转到 HTTPS，不接收密码 |
| 服务器 IP或其他域名 | 不提供网站内容 |

配置保护首页、深层路由、静态资源和 `/data/radar.json`。不能只检查首页。

## 2. 服务器准备

在 Ubuntu ECS 上安装 Nginx、密码工具和 Fail2ban：

```bash
sudo apt update
sudo apt install nginx apache2-utils fail2ban
sudo install -d -m 750 -o root -g www-data /etc/nginx/biaokankan
```

HTTPS 证书必须同时覆盖：

```text
biaokankan.com
www.biaokankan.com
```

Nginx 配置默认从下面位置读取证书：

```text
/etc/letsencrypt/live/biaokankan.com/fullchain.pem
/etc/letsencrypt/live/biaokankan.com/privkey.pem
```

证书位置不同时，只修改服务器上的证书路径，不把证书复制进仓库。

## 3. 配置公司网络白名单

先在公司网络确认对外显示的公网 IPv4；启用了 IPv6 时同时确认 IPv6 网段。填写公网地址，不能填写 `192.168.x.x`、`10.x.x.x` 等局域网地址。

以仓库里的 `deploy/china/trusted-networks.conf.example` 为格式，在服务器创建：

```text
/etc/nginx/biaokankan/trusted-networks.conf
```

实际内容示例：

```nginx
allow 真实公网IPv4/32;
allow 真实公网IPv6网段;
```

保存后执行：

```bash
sudo chown root:www-data /etc/nginx/biaokankan/trusted-networks.conf
sudo chmod 640 /etc/nginx/biaokankan/trusted-networks.conf
```

公网 IP 发生变化时，旧地址必须删除。不要为了避免维护而放宽成运营商的大网段。

## 4. 给企业创建独立凭证

第一家企业使用 `-cB` 创建 bcrypt 密码文件：

```bash
sudo htpasswd -cB /etc/nginx/biaokankan/.htpasswd enterprise-a
```

后续企业不能再加 `-c`，否则会覆盖已有企业：

```bash
sudo htpasswd -B /etc/nginx/biaokankan/.htpasswd enterprise-b
sudo htpasswd -B /etc/nginx/biaokankan/.htpasswd enterprise-c
```

命令会安全提示输入密码。不要使用 `-b` 把密码放进命令行，也不要把真实用户名、密码或 `.htpasswd` 提交到仓库。

```bash
sudo chown root:www-data /etc/nginx/biaokankan/.htpasswd
sudo chmod 640 /etc/nginx/biaokankan/.htpasswd
```

撤销某家企业时只删除它自己的用户名：

```bash
sudo htpasswd -D /etc/nginx/biaokankan/.htpasswd enterprise-b
```

## 5. 安装配置并启用失败限速

将仓库文件安装到服务器对应位置：

```text
deploy/china/nginx.conf
  → /etc/nginx/conf.d/biaokankan.conf

deploy/china/fail2ban/filter.d/biaokankan-auth.conf
  → /etc/fail2ban/filter.d/biaokankan-auth.conf

deploy/china/fail2ban/jail.d/biaokankan-auth.local
  → /etc/fail2ban/jail.d/biaokankan-auth.local
```

如果 `/etc/nginx/conf.d/default.conf` 仍会提供默认网站，先从 Nginx 启用目录移走，不能让服务器 IP 命中另一个公开站点。

每次修改先做访问控制启动检查和 Nginx 配置检查，再重新加载：

```bash
sudo sh /项目目录/deploy/china/check-access-control.sh
sudo nginx -t
sudo systemctl reload nginx
sudo fail2ban-client reload
sudo fail2ban-client status biaokankan-auth
```

任何一步失败都停止操作，保持上一份可工作的 Nginx 配置。

## 6. 上线验收

按下面四种网络分别测试，不以服务器本机 `curl` 代替真实外网测试：

1. 公司 Wi-Fi：打开首页、项目详情和 `/data/radar.json`，均不要求密码；
2. 手机关闭 Wi-Fi：所有入口先要求密码，三家企业凭证分别可以进入；
3. 手机流量输入错误密码：返回 401，连续失败 5 次后 Fail2ban 出现封禁记录；
4. 服务器 IP、GitHub Pages 地址和旧部署地址：均不能读取页面或数据。

正式交付前还要在 GitHub 仓库设置中关闭 Pages。代码工作流已经改为只构建验证，**停止工作流发布不会自动删除此前已经发布的 Pages 网站**。

## 7. 回滚

回滚只恢复上一份已验证的 Nginx 配置，不删除证书、白名单或密码文件。恢复前后都执行 `sudo nginx -t`，通过后才重新加载。

第一阶段凭证只用于封闭试用。第二阶段账号系统上线后，先确认三家企业的真实用户均已激活，再删除全部第一阶段企业凭证。
